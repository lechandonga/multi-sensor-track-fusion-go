# multi-sensor-track-fusion-go

纯本地、确定性、可复现的多传感器目标跟踪融合组件（激光 / 雷达 / 相机）。
不接真实设备、不依赖外部服务、不需要联网；除 Go 标准库外无任何第三方依赖。

## 目录结构

- `tracker/`：融合核心（接入校验、时钟修正、关联、融合、冲突取舍、生命周期、快照、重放）。
- `simulate/`：固定种子的本地数据模拟，制造遮挡、随机丢检、乱序、重复帧和传感器冲突。
- `cmd/demo/`：一键演示程序。

## 本地验证

```bash
# 运行演示（无需联网、无需设备）
go run ./cmd/demo

# 运行全部单测
go test ./...

# 开启竞态检测（推荐），并查看每个业务用例的覆盖日志
CGO_ENABLED=1 go test -race -v ./tracker/
```

演示会打印：重复帧拒绝、超迟 / 异常时间戳拒绝、遮挡期间 `coasting`、判丢与续接、
冲突取舍记录、最终轨迹以及重放复现结论。

## 传感器数据约定

- 所有传感器先通过 `tracker.New` 注册，携带固定属性：`ID`、`Kind`、`ClockOffset`、`Priority`。
- 输入为 `Frame`：传感器 ID、单调递增的帧序号 `Seq`、该传感器自身时钟上的 `RawTime`、
  以及若干 `Detection`（统一公共坐标系下的 x/y，可选速度 vx/vy 与类别）。
- 每路传感器按自己的节奏推送，允许乱序、重复、迟到；帧是幂等接入的。
- 模拟数据的坐标系、噪声、丢检率与时钟偏差见 `simulate/simulate.go`。

## 时间约定（固定规则，不随到达顺序漂移）

1. **固定时钟偏差**：每帧统一时间 = `RawTime + Sensor.ClockOffset`。偏差在配置时
   声明，**不做在线估计**，因此送达顺序不会把时间轴越带越偏。
2. **规范处理顺序**：全部已接受帧按 `(统一时间, 传感器优先级, 传感器 ID, 序号)` 排序后处理，
   与物理到达顺序无关，这是重放可复现的基础。
3. **帧校验与拒绝类别**（均返回 `*FrameRejectedError`，`Kind` 标明问题类别）：
   - `duplicate`：同传感器 `Seq` 已接受过；原帧原样或改动后再送都幂等拒绝，绝不重复累计。
   - `too_late`：修正后时间早于**该传感器**已接受水位 `MaxLateArrival` 以上，超出可修正范围。
     迟到窗口按每路自身时间轴衡量，多路并发不会因另一路时钟领先而误伤。
   - `out_of_order`（窗口内乱序）：序号更新但时间在窗口内倒退，属于可修正迟到，予以接受，
     由规范排序在时间轴上归位，历史自洽。
   - `from_future`：超前全局已知最大时间超过 `MaxFutureSkew`。
   - `bad_timestamp`：零值等非法时间戳。
   - `unknown_sensor`：帧来自未注册传感器。

## 关联规则

- 目标按匀速模型由上一确定状态预测到帧时刻，门限采用随时间膨胀的位置标准差
  （观测噪声 + 过程噪声），标准化距离在 `GateRadius` 内才允许关联。
- 多路观测到目标用**贪心全局最近邻（GNN）**分配：距离升序；距离相同按轨迹 ID、
  检测序号决胜，保证无随机性。
- 同一时刻被多路看到的一致观测只产生**一条轨迹、一个稳定 ID**；轨迹 ID 在目标
  生命周期内不变。同时刻的一致观测在轨迹历史中合并为 `fusion` 节点。

## 目标生命周期

- 新检测先建**候选**目标（`tentative`），累计命中达到 `ConfirmHits` 才确认
  （`confirmed`）；候选不对外暴露，超过 `TentativeTTL` 未确认则静默丢弃。
- 确认目标丢检后进入 `coasting`：以匀速外推维持，快照仍可见，`CoastFrames` 记录
  连续错过的帧数；超过 `CoastTime` 才明确判为 `lost`。
- `lost` 目标在 `ReacquireTime` 续接窗口内重新被看到，且落在关联门内：
  **沿用原 ID**（历史节点标注 `reacquired after coasting`）；超过续接窗口再出现，
  或已被其它目标占据：作为**新目标分配新 ID**。续接窗口结束后目标从快照消失。
- 任意时刻查询都基于轨迹历史节点做 as-of 推导，看到的是该时刻的一致状态，
  不会出现同一目标在同一快照里出现两次。

## 冲突处理策略（有依据、可审计、不偷偷混合）

- 同一时刻已有另一路传感器的观测被采用时，若两条观测的标准化位置差超过
  `ConflictRadius`（但仍在关联门 `GateRadius` 内），判定为**冲突观测**。
- 取舍规则固定：**传感器优先级数值小者胜**（默认 lidar < radar < camera）；
  平级再按传感器 ID 决胜。由于规范顺序保证高权威者先处理，冲突中的后到观测被拒绝。
- 被拒绝的冲突观测**绝不与采纳值加权混合**，也不会新建出第二条轨迹；其数值、类别
  与取舍规则写入 `Conflicts()` 记录，可通过 ID 追溯到具体时刻与目标。
- 类别采用固定权重投票（权重 `1/(Priority+1)`），平票按类别名字典序决胜；
  被拒绝的冲突类别不参与投票。
- 无冲突时位置用 EMA 系数 `FusionAlpha` 融合到预测值；有速度能力的传感器直接
  融合速度，无速度传感器用相邻位置差做半权速度估计。

## 快照与重放一致性

- 写入采用"接收独立数据 → 加锁 → 规范排序 → 从零重建到独立状态"的方式，
  读者只会看到完整状态，看不到更新到一半的中间结果。
- 单一 `sync.RWMutex` 保护全部状态，多传感器可并发写、查询可并发读。
- `Snapshot(at)` 返回 `at` 时刻的深拷贝；`AcceptedFrames()` 按规范顺序导出帧；
  `Replay(cfg, sensors, frames)` 在全新实例（等价于重启）上重建。同一段数据
  重放两次或重启后再灌，轨迹、ID、逐节点历史逐字节一致（有单测断言）。

## 可配置项（`tracker.Config`）

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `MaxLateArrival` | 500ms | 允许的最大迟到量（按每路自身时间轴） |
| `MaxFutureSkew` | 2s | 时间戳允许超前全局水位的上限 |
| `GateRadius` | 8.0 | 关联门限（标准化距离） |
| `ConflictRadius` | 3.0 | 门内观测判为冲突的标准化距离阈值（须小于 GateRadius） |
| `PositionSigma` / `VelocitySigma` | 0.5 / 1.0 | 观测噪声标准差 |
| `ProcessSigma` | 0.3 | 匀速预测的过程噪声 |
| `ConfirmHits` | 2 | 候选转确认所需命中数 |
| `CoastTime` | 400ms | 允许的连续丢检时长，超过判 lost |
| `TentativeTTL` | 1s | 候选目标存活时长 |
| `ReacquireTime` | 2s | 判丢后的续接窗口 |
| `DeadHistoryTime` | 10s | 已终结轨迹在内存中的保留时长 |
| `FusionAlpha` | 0.6 | 无冲突 EMA 融合系数 |
| `TrackIDPrefix` | `T` | 目标 ID 前缀 |

## 单测覆盖的业务

- 遮挡 / 短时丢检：`coasting` 外推、判丢边界、窗口内续接原 ID、超窗新建。
- 跨传感器重复：三路同时观测只产生一条稳定 ID 轨迹，来源与融合节点可查。
- 乱序与超迟：窗口内乱序接受、重复帧幂等拒绝、超迟 / 未来 / 零时间戳 / 未知传感器分类拒绝。
- 冲突观测：按权威优先级取舍、冲突值与类别不被混合、冲突留痕。
- 固定时钟偏差：不同到达顺序结果一致。
- 并发读写：4 读者 × 3 写者并发，`-race` 下结果与串行基线一致。
- 重放复现：导出后 Replay 与全新实例再灌，轨迹、ID、逐节点历史完全一致。
